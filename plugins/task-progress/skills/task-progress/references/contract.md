# Контракт safe snapshot v1

Это явно подготовленная небольшая проекция данных, не экспорт Planner целиком. Renderer только читает её; он не открывает ссылки evidence и не подтверждает правдивость внешних утверждений. Не помещать секреты и персональную переписку. Исполняемая спецификация — `scripts/core.mjs`, функции validateSnapshot/validateProgress; неизвестные поля запрещены. Лимит файла/stdin 256 КиБ, не более 100 задач.

Корень:

| Поле | Значение |
|---|---|
| schemaVersion | 1 |
| demo | необязательный boolean; true выводит заметную метку синтетических данных |
| selection | `{kind, id}`; kind task/project/portfolio; для tasks также обязательны уникальные taskIds |
| staleAfterMinutes | 1–10080, явный порог свежести |
| tasks | список задач |
| aggregation | null или состав/веса конкретной области |

Задача:

| Поле | Значение |
|---|---|
| id, title | устойчивый ID и короткое название |
| projectId, portfolioId | ID родительских областей или null; не объединять по названию |
| status | working/checking/blocked/paused/unknown/accepted |
| stage | короткая текущая стадия или null |
| stages | необязательный отдельный перечень `{source,items}` для отображения; не участвует в расчёте процента |
| updatedAt | время наблюдения состояния/оценки ISO 8601 с зоной или null |
| dataStatus | ok/error/unknown |
| dataError | необязательное короткое безопасное описание ошибки |
| accepted | до 8 `{label,evidence}` — только действительно принятые результаты |
| blockers | до 8 коротких препятствий/оставшихся обязательных шагов |
| acceptance | null или `{acceptedAt,evidence}` для приёмки ВСЕЙ задачи |
| progress | объект ниже |

ID: до 128 букв/цифр и `_.:-`, текстовые значения ограничены длиной. Даты с невозможным календарным днём не допускаются. updatedAt должен отражать возраст самой оценки; повторное открытие файла не делает её свежей. Порог допуска часов источника — 1 минута в будущем; большее расхождение означает неизвестную свежесть.

## Этапы для отображения

Рядом с фиксированной или примерной оценкой можно передать явный план этапов:

```json
{
  "source": { "ref": "safe:plan-v1", "evidence": "Согласованный перечень этапов" },
  "items": [
    { "id": "requirements", "label": "Требования", "status": "accepted", "evidence": "safe:requirements-accepted" },
    { "id": "implementation", "label": "Разработка", "status": "working" },
    { "id": "validation", "label": "Проверка", "status": "pending" },
    { "id": "release", "label": "Выпуск", "status": "unknown" }
  ]
}
```

Это значение поля `task.stages`, а не отдельный корневой объект. Допустимы 1–40 элементов с уникальными ID и подписями до 200 символов; статусы: pending, working, checking, accepted, unknown, blocked, paused. Для accepted обязательно непустое evidence. Источник перечня обязателен. Его свежесть определяется тем же `task.updatedAt` и `dataStatus`; старые этапы показываются как данные последнего снимка.

Перечень только поясняет работу: он не изменяет fixed checklist28%, веса, общую оценку или приёмку всей задачи. Не выводите из количества отмеченных этапов новый процент. При отсутствии явного перечня renderer сообщает «Этапы не переданы». Не выдумывайте этапы из одного текстового `task.stage`.

Если процент уже рассчитывается через `progress.basis=stages`, используется существующий `progress.stages`; второй перечень `task.stages` одновременно запрещён. Нормализованный JSON-отчёт содержит `stages`, `stageSource` (display/progress/null) и `stageSourceEvidence`; это добавочные поля, исходные формулы сохранены.

Progress:

```json
{
  "basis": "fixed_checklist",
  "scope": { "kind": "task", "id": "task-123" },
  "value": 28,
  "source": { "ref": "safe:checklist-v3", "evidence": "Принята именно оценка 28%" }
}
```

- `basis=unknown`: value=null, source=null либо безопасная ссылка на причину unknown.
- `basis=estimate`: value — конечное число или `{min,max}`, 0≤min≤max<100; source обязателен. Нулевое значение — отдельное явное утверждение с источником, не замена null.
- `basis=fixed_checklist`: одно принятое число, без пересчёта. Необязательный `visualEstimate:{value,source}` демонстрирует конфликт с визуальным впечатлением: renderer его не применяет. Если принятого числа нет — value=null.
- `basis=stages`: value=null, source обязателен, stages — 1–40 уникальных `{id,label,weight,status,evidence?}`. weight конечный, >0 и ≤1e9. status pending/working/checking/blocked/paused/accepted/unknown. Только accepted с evidence добавляет вес. Известные pending/working/checking/blocked/paused дают 0 вклада. Доля = 100×Σ весов принятых этапов / Σ всех весов; unknown любого этапа делает текущий процент задачи неизвестным, при этом принятый вес и охват этапов показываются отдельно. Полное принятие этапов ещё не доказывает приёмку всей задачи.

Если готовой оценки нет, автор снимка может построить примерную оценку **из явного плана той же задачи** и датированных подтверждений его шагов. Передайте полный состав обязательных этапов, точный `scope` и ссылку на план в `progress.source`. Если план содержит веса, сохраните их. Иначе равные веса допустимы лишь как объявленная в `source.evidence` методика примерной оценки; не называйте её принятым checklist. Для каждого `accepted` требуется свидетельство выполнения именно критерия этого этапа. Незавершённые этапы получают известный статус; неизвестный статус остаётся `unknown` и отключает текущий общий процент. Время `task.updatedAt` относится к наблюдённым сведениям, а не к записи нового JSON. Не заменяйте существующее принятое значение `fixed_checklist`, не назначайте этапы из одной фразы о текущей работе и не переносите оценку другой области.

Пример для плана с тремя обязательными шагами без собственных весов (равные веса явно объявлены источником):

```json
{
  "basis": "stages",
  "scope": { "kind": "task", "id": "task-123" },
  "value": null,
  "source": { "ref": "safe:task-123-plan", "evidence": "Три обязательных этапа плана; равные веса 1:1:1 — методика примерной оценки" },
  "stages": [
    { "id": "package", "label": "Пакет проверен", "weight": 1, "status": "accepted", "evidence": "safe:package-check-pass" },
    { "id": "install", "label": "Установка", "weight": 1, "status": "blocked" },
    { "id": "verify", "label": "Проверка проекта", "weight": 1, "status": "pending" }
  ]
}
```

Это **примерно 33,33% по выбранной модели**, а не приёмка всей задачи; при новом доказательстве измените снимок и время наблюдения. Если плана нет, сохраните `basis=unknown`, а список этапов не изобретайте. Renderer получает готовый safe snapshot и сам не ищет план или evidence в файлах и сервисах.

Scope оценки должен быть task с тем же id, что и задача. Портфельная оценка 91% в scope portfolio не становится прогрессом выбранной task. Fixed28 не заменяется visual70. Финальные 100% требуют status=accepted, отдельного непустого acceptance.evidence, датированной приёмки не позже updatedAt, отсутствия открытых blockers и свежего состояния. Fixed checklist ниже 100 при флаге accepted считается противоречием; renderer не повышает его. Source не подписан криптографически: факт внешней приёмки отвечает источнику, не renderer.

Старая дата, ошибка источника, неизвестная дата/статус или далёкая будущая дата исключают оценку из текущей. Последнее валидное число показывается отдельно как последняя оценка; unknown не превращается в 0.

Aggregation:

```json
{
  "scope": { "kind": "project", "id": "project-123" },
  "members": [{ "taskId": "task-123", "weight": 3 }, { "taskId": "task-456", "weight": 1 }],
  "source": { "ref": "safe:membership-v2", "evidence": "Это полный состав выбранной области; веса согласованы" }
}
```

Для scope tasks требуется такое же id, как у selection tasks, и точное совпадение taskIds с members. Scope task не агрегируется. Состав project/portfolio утверждается источником явно; renderer не может узнать о неуказанных задачах. Задача, ожидаемая в members и отсутствующая в tasks, остаётся видимой строкой unknown. Чужое членство или лишняя строка выключают итог. Без состава/весов именно выбранной области общая оценка неизвестна, равные веса молча не назначаются.

При полном охвате: по каждому концу диапазона `Σ(progress_i×weight_i)/Σ(weight_i)`.
При неполном: общий процент=null; отдельно среднее известной части `Σ_known(progress_i×weight_i)/Σ_known(weight_i)` и охват `Σ_known(weight_i)/Σ_all(weight_i)`. Полный знаменатель и слагаемые видны в выводе. Нет известных задач — среднее=null, деление на 0 не выполняется; 0% охвата не является 0% прогресса. Общие 100% допустимы лишь при приёмке каждого участника.

Примеры лежат в корневой `examples/` плагина. Для воспроизведения датированного примера используется `--at 2026-10-21T12:10:00Z`. В рабочем показе `--at` не передавать: это воспроизведение, не обновление evidence.
