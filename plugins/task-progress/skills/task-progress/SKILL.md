---
name: task-progress
description: Показывать примерный прогресс одной или нескольких задач в Codex по явно выбранным безопасным данным, с областью, принятой оценкой, препятствиями и свежестью.
---

Покажи прогресс по-русски через renderer `scripts/render.mjs`. Доступны «Полоса» и «Круг», темы «Ночная», «Светлая», «Индиго», «Лесная» и отображение этапов. Для одной явно выбранной задачи HTML начинает с компактной карточки: читаемый процент или «?», линия переданных этапов и кнопка «Подробнее» для раскрытия полного «Пульта задач». В раскрытии название задачи показано один раз; прогресс, состояние и вертикальный маршрут с ровной линией между узлами читаются без повторного технического заголовка. Для областей из нескольких задач полный пульт открыт сразу. Выбор вида, темы и показа этапов находится в его закрытой по умолчанию панели «Настройки отображения». Темы представлены круглыми значками без видимых подписей, но с доступными названиями и подсказками. Начальные вид и тема — полоса и ночная; учитывай явно выбранные пользователем настройки. Карточка находится в ленте беседы и не закрепляется над полем ввода. Это вывод по запросу; сами данные не обновляются.

1. Установи точную выбранную область: task, project, portfolio либо именованный tasks с taskIds. Смена задачи меняет область; не переноси портфельный процент в задачу. Если выбор неоднозначен, уточни только выбор, сохранив unknown.
2. Прими явно указанный файл `*.safe.json` или подготовленные в контексте данные по [контракту](references/contract.md). Для самого показа читай только этот файл; ссылки evidence из него не открывай автоматически. Не ищи .env, секреты, переписку, STATE/NEXT. Если безопасных данных нет, покажи «неизвестно» и назови недостающее.
   Если оценка отсутствует, а текущее поручение позволяет подготовить данные, сначала сверь **точный ID задачи**, явный план её обязательных этапов и датированные подтверждения результатов в уже определённых материалах этой задачи. Подготовь отдельный `*.safe.json` по контракту: `basis=stages`, `value=null`, полный перечень этапов плана с весами и источник плана/методики. Если план не задаёт весов, допускаются равные веса как **явно объявленное допущение примерной оценки**, а не как принятая оценка. Только этап с подтверждением выполнения своего критерия получает `accepted` и evidence; текущая работа, проверка или готовый запрос сами по себе не являются приёмкой. Остальные этапы отмечай по известному состоянию `pending`, `working`, `checking`, `blocked` или `paused`; если статус неизвестен, укажи `unknown` и оставь общий процент неизвестным. Причину блокировки также передай через `task.status=blocked`/`blockers`. `updatedAt` должен отражать время проверенного состояния, а не время создания нового файла. Не подменяй уже принятую оценку `fixed_checklist`, не придумывай этапы и не выдавай старое свидетельство за текущее. Если явного плана или нужных подтверждений нет, сохрани unknown и объясни причину.
3. Выполни renderer. Пути разрешай относительно фактической папки установленного skill, а не исходного проекта. Для графического вывода добавь `--format html`:

   ```powershell
   node '<SKILL_DIR>/scripts/render.mjs' --input '<явный путь>/progress.safe.json' --task '<taskId>' --format html
   node '<SKILL_DIR>/scripts/render.mjs' --input '<явный путь>/progress.safe.json' --scope 'project:<projectId>' --format html
   node '<SKILL_DIR>/scripts/render.mjs' --input '<явный путь>/progress.safe.json' --task '<taskId>' --format html --view ring --theme light --stages show
   ```

   Для данных, уже переданных в чате, можно передать JSON в stdin (`--stdin`) через инструмент, умеющий передавать stdin без интерполяции shell; не вставляй пользовательский JSON в исполняемую командную строку. Не создавай файл при режиме только чтение. Для нескольких явных taskId применяй `--tasks 'id-1,id-2'`.
4. Если клиент поддерживает inline-визуализацию и разрешено создание файла, сохрани полученный HTML fragment без переделки в UTF-8 в папке визуализаций текущего чата или в разрешённой рабочей папке. Используй абсолютный путь и покажи в финальном ответе отдельную строку `visualize{"path":"<абсолютный-путь>/task-progress.html"}`. Для одной задачи сначала открой «Подробнее», затем «Настройки отображения», если нужно переключить форму, тему или этапы. Для нескольких задач пульт открыт сразу, а панель настроек закрыта. Переключение работает локально и не меняет данные; источники раскрываются. Плавное раскрытие в поддерживаемом клиенте отключается при `prefers-reduced-motion`; без поддержки анимации остаётся обычное раскрытие. HTML содержит только собственный скрипт управления отображением, без сетевых обращений и записей в исходные данные. Не выводи код HTML в чат и не отправляй файл в Library. Для самого renderer это по-прежнему только чтение входа и вывод в stdout; запись fragment выполняет вызывающий инструмент.
5. При отсутствии этой поверхности, явном запросе текстового формата или режиме «только чтение» вызови `--format markdown` и выведи результат обычным текстом чата. Это также формат CLI по умолчанию. Не прячь его в code fence. `--format json` предназначен для структурированной проверки. В любом формате сохраняй область, unknown, источник, свежесть, приёмку и ограничения охвата; не пересчитывай проценты самостоятельно. При ненулевом завершении renderer сообщи «прогресс неизвестен», короткую причину и код ошибки; не подставляй 0% или предыдущий процент как текущий.

Принятый fixed_checklist имеет приоритет над visualEstimate. Дроби этапов считает код, только принятые этапы дают вклад; работа, проверка, запущенный исполнитель, принятый запрос и время не доказывают завершение. 100% требует статуса accepted и отдельного датированного evidence приёмки. Старая/ошибочная оценка показывается как последняя, а текущая остаётся неизвестной.

Для этапов используй переданный `progress.stages` при расчёте по весам либо отдельный `task.stages={source,items}` для пояснения фиксированной/примерной оценки по [контракту](references/contract.md). Отдельный перечень не пересчитывает процент. Если явного плана нет, оставь «Этапы не переданы». Не назначай accepted из факта работы или проверки. `--view bar|ring`, `--theme night|light|indigo|forest`, `--stages show|hide` задают начальный вид только для HTML; переключение не меняет evidence, текущую оценку и область.

Renderer не проверяет правдивость внешних evidence и не обновляет Planner. Не создавай фоновые опросы, автоматизации, отправки или API-вызовы. При повторном запросе получи свежий safe snapshot в уже разрешённых пределах; не выдавай старый вывод за живой.
